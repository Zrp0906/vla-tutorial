# 12｜SmolVLA 进阶功能路线

[全部教程](../../README.md) · [上一篇：11｜实验总结与下一步改进](../p11_feedback_summary/11_实验总结.md)

## 这一部分介绍什么

本章列出二维推块项目待实现的功能。每项扩展都可以单独实现和验收。

## 任务与控制功能

| 功能 | 要新增什么 | 完成后能做什么 |
| --- | --- | --- |
| 多物体、多步指令 | 给方块和目标区增加颜色或编号。为每条指令定义目标对象、目标区和子任务顺序，并记录当前完成到哪一步。 | 执行「先把红块推到左边，再把蓝块推到右边」。仿真可以分别判断推错物体、推错位置和漏做步骤。 |
| 遥操作与专家接管 | 增加键盘或手柄控制、录制和回放。允许在模型操作时切换到人工或脚本专家，并给纠正片段加上来源标记。 | 人可以演示新任务，也可以在模型推歪时接管，把纠正动作加入下一轮监督微调的数据。 |
| 训练断点续跑 | 增加 `--resume`，恢复模型或适配器、优化器、学习率调度、随机状态和数据读取进度。 | 从指定检查点继续同一次训练，接续已有的训练进度与日志。 |
| 异步推理与动作队列 | 将仿真控制端和推理服务分开。控制端按固定节拍执行队列中的动作，服务端根据新观测生成下一批动作。为观测和动作记录时间戳，处理队列耗尽和过期动作。 | Windows 使用 CUDA 推理，Mac 负责仿真和界面。执行当前动作时，可以同时计算后续动作。 |
| 接入真实机械臂 | 将仿真的观测和动作接口替换为相机、机械臂状态和控制命令，加入坐标标定、动作限幅、急停和人工接管。 | 采集真实抓取或搬运示范，并用对应的动作空间训练和运行策略。 |

多物体任务可以从**两种颜色、两个目标区、两条有顺序的子指令**开始。先让仿真正确判分，再扩展脚本专家和示范录制。若优先做两台电脑协作，则先把现有推理调用拆成 **Mac 控制端与 Windows 推理端**，验证固定节拍和队列行为，再增加异步补充动作。

## 按模型全流程扩展

沿用《模型从数据到部署流程》的六个板块，可以把 SmolVLA 扩展成一套能换数据、换模型、换训练方法和换部署版本的工作流。 [模型从数据到部署流程](../../../模型从数据到部署流程.md)

| 全流程板块 | 可以增加的功能 | 交付物 |
| --- | --- | --- |
| 需求与数据准备 | 用配置定义任务、成功条件、观测字段、动作单位和控制频率。统一导入仿真、遥操作与纠偏轨迹，检查缺帧、时间对齐、异常动作和跨集合重复场景。 | 任务配置、带版本的数据集清单、质检报告。可沿用 [LeRobotDataset v3.0 的轨迹与元数据结构](https://huggingface.co/docs/lerobot/v0.4.4/lerobot-dataset-v3)。 |
| 基础模型获取与基线评测 | 提供可替换基座的适配接口，核验许可、权重完整性和观测与动作兼容性，让新接入的轻量策略能使用同一套场景。 | 模型注册清单和基座适配器。 |
| 继续训练与后训练 | 增加领域继续训练、全量微调、轨迹偏好、端到端强化学习和蒸馏。记录各候选模型使用的数据版本和训练配置，支持断点续跑、混合精度与梯度累积。 | 可选训练路线、训练记录和可恢复的检查点。 |
| 模型效果验收 | 增加按物体、指令和场景条件分组的测试集。针对新版本做旧任务回归，并支持从运行日志重现失败场景。 | 分组评测报告、回归通过条件和场景重放工具。 |
| 部署准备与验证 | 增加统一导出入口和部署清单，按目标设备接入低位推理后端。为每种候选部署版本增加自动重载检查和资源、延迟门槛。 | 统一部署清单、目标后端与部署前验收工具。 |
| 使用与反馈闭环 | 给推理请求和运行轨迹记录模型版本。服务可以切换版本并回退。把失败、人工接管和超时记录分开，审核后将可用的纠正轨迹纳入下一版训练数据。 | 可切换的推理服务、运行日志、待标注队列和新数据版本。版本与运行记录可以参照 [模型注册表的版本管理方式](https://mlflow.org/docs/latest/model-registry/)。 |

### 训练路线和数据怎么配

- **继续预训练或领域适配**。如果要适应新的场景和视角，可以先收集相关图像或视频，为视觉骨干设计领域训练目标，再用动作示范完成任务微调。
- **全量微调**。增加可解冻视觉编码器和完整文本骨干的训练分支，继续用专家示范监督动作。记录实际参与更新的层和训练资源占用。
- **偏好优化**。从同一初始状态和指令生成两段动作，标出哪段更好，例如完成任务且动作更平稳。先实现偏好数据的采集和检查，再选用适配连续动作 Flow Matching 的训练目标。 [面向 Flow Matching VLA 的偏好优化示例](https://arxiv.org/abs/2606.05468)
- **端到端强化学习**。增加一条直接更新 Flow Matching 动作策略的训练路线，保存交互轨迹、奖励和策略检查点。
- **蒸馏**。用经过筛选的教师动作块或闭环轨迹训练轻量学生。学生沿用同一套观测、动作和评测接口，便于替换部署。
- **量化感知训练**。给轻量学生加入训练时的量化模拟，导出后用同一批任务复测。

### 可以先做的一条完整路线

用 `dataset_id`、`run_id` 和 `model_version` 串起各阶段。先增加数据版本与质检清单，再为候选模型登记训练来源和验收记录。最后让 Windows 推理服务报告所加载的版本，把经审核的纠正轨迹回收到下一版数据。
