## 这一部分介绍什么

做饭先检查锅和炉子；训练模型先检查 Python、依赖和计算设备。这一步不教机器人，只确认工具能否使用。

## 使用说明与前提

先读第 00 篇。已有的 `embodiedai` 是本项目的环境；不要因为看到缺包，就随意把依赖装到系统 Python。

```bash
cd /Users/zrp/Desktop/lora
conda run -n embodiedai python smol/smol_workflow/p01_environment/01_01_check_environment.py --config smol/configs/standard.json --run-dir smol/outputs/lesson_run --device auto
```

## 输入和输出

输入是现有环境、标准配置和选定设备。输出在本次运行目录：

- `config.json`：这次实验实际使用的配置。
- `reports/environment.json`：Python、PyTorch、设备等检查信息。
- `reports/requirements.lock.txt`：当时环境中的依赖版本快照。
- `reports/pip_check.txt`：依赖兼容性检查结果。

锁定清单是“拍照留档”，不是本阶段已经创建了一个新环境。

## 检查清单：如何判断完成

看 `stages/01.json` 是否完成，再看环境报告的设备与依赖检查细节。不要只看“电脑型号正确”。

如果报 `ModuleNotFoundError`，意思是当前环境缺模块；先确认环境选对、对照 `smol/requirements.txt`，再决定是否修依赖。若遇到共享内存或 MPS 权限问题，先排查进程运行限制，不要据此断言硬件不支持。
