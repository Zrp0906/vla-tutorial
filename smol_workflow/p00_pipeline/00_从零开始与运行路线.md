## 这一部分介绍什么

把整个项目想成“教一个小机器人推方块”。它先看老师示范，再练习，最后独立考试。本项目的机器人是屏幕上的二维推动器，不是真实机械臂。

学习路线是：检查电脑 → 检查游戏 → 收集示范 → 整理数据 → 检查原来的模型 → 两种训练 → 考试 → 整理模型 → 服务测试 → 写总结。训练不是第一步。

第一次读时，先看每篇的介绍、使用说明和检查清单；公式可以第二遍再看。不懂希腊字母不影响先理解故事。

## 先认识几个词

| 词              | 白话解释        | 本项目中的意思       |
| -------------- | ----------- | ------------- |
| episode／回合     | 从开局到结束的一次游戏 | 一条完整推块轨迹      |
| frame／帧        | 小电影中的一张照片   | 某一步的画面        |
| action／动作      | 下一步向哪里走     | 两个数：左右、上下     |
| batch／一批       | 一次交给老师的几份作业 | 默认 2 个动作窗口    |
| epoch／轮        | 把练习册完整学一遍   | 默认训练 2 轮      |
| weight／权重      | 模型内部可调整的小旋钮 | 训练修改的数字       |
| checkpoint／检查点 | 保存下来的练习进度   | 某轮结束的模型包      |
| inference／推理   | 用已经学到的东西做题  | 输入画面，输出动作     |
| JSON           | 带名字的数字和文字清单 | 配置、数据索引、报告    |
| `_impl`        | 入口后面的内部实现   | 被导入调用，不要逐文件运行 |

`p06` 表示第 06 阶段；`06_01` 表示这一阶段的第一个入口。`__init__.py` 是 Python 包文件，不是执行步骤。

## 使用说明：先看顺序

以下命令可以直接在终端粘贴。我们始终使用已有的 `embodiedai` 环境，不另建环境。

```bash
cd /Users/zrp/Desktop/lora
conda run -n embodiedai python smol/smol_workflow/p00_pipeline/00_01_check_structure.py
conda run -n embodiedai python smol/smol_workflow/p00_pipeline/00_02_run_pipeline.py --dry-run
```

第一条 Python 命令检查文件组织、导入和参数；第二条只打印执行计划，不下载、不采集、不训练。`conda run -n embodiedai` 的意思是“用这个已存在的工具箱运行后面的程序”。

## 使用说明：真正执行时二选一

方法 A：让总入口按顺序执行全部阶段。下面这条会真正下载、采集、训练和评测，不是预览！

```bash
conda run -n embodiedai python smol/smol_workflow/p00_pipeline/00_02_run_pipeline.py --config smol/configs/standard.json --run-dir smol/outputs/lesson_run --device auto
```

方法 B：按后面各篇给出的单步命令执行。不要在方法 A 跑完后，又向同一个目录重复采集、训练。

只执行某一段，可以用总入口的 `--from-stage` 和 `--to-stage`。例如下面只跑阶段 01–02：

```bash
conda run -n embodiedai python smol/smol_workflow/p00_pipeline/00_02_run_pipeline.py --config smol/configs/standard.json --run-dir smol/outputs/lesson_run --device auto --from-stage 1 --to-stage 2
```

范围跳转不会补齐缺失的上游数据。阶段 05 包含下载和基线评测两个脚本；它们仍属于同一个阶段。某一步失败，总入口会停止。
